## หน้าตา/การใช้งาน (UI) — กติกาที่ต้องรักษา

> จาก UX review 9 ส.ค. 2569 ที่ตรวจด้วย **หน้าจอจริง** (ยก `php -S` + ใส่ข้อมูลเสมือนร้านจริง
> แล้วเปิดดูทั้ง 1280 และ 375 พร้อมวัดขนาดปุ่ม/คอนทราสต์จากหน้าจริง)
> ⚠️ ตรวจ UI จาก markup อย่างเดียวมองไม่เห็นปัญหาพวกนี้เลยสักข้อ

- ⚠️⚠️ **ตารางทุกตัวต้องมีคลาส `table-cards`** — บนจอ **< 1024px** แถวจะกลายเป็นการ์ด 1 รายการ/1 ใบ
  · ⚠️ **จุดสลับคือ 1024 ไม่ใช่ 768** — เคยตั้งไว้ 767 แล้วไอแพดแนวตั้ง (768) ตกอยู่ในช่องว่าง:
    กลับมาเป็นตารางเต็มซึ่งกว้างเกินจอชนิดนั้นอยู่ดี · วัดจริงที่ 768: ตาราง 2,249px ในกรอบ 694px
    → **ซ่อนไป 1,555px** ผู้ใช้ไอแพดได้ประสบการณ์แย่กว่าทั้งมือถือและคอม
  · ⚠️⚠️ **ช่องที่ผู้ใช้พิมพ์เองต้องมีเพดานความกว้าง + ตัดบรรทัดได้** (`lg:max-w-[16rem]` ที่ช่องโน้ต)
    แถวตั้ง `whitespace-nowrap` ไว้ให้ตัวเลขไม่ตัดคำ แต่โน้ตยาวได้ถึง 255 ตัว · วัดจริงบนจอ **1280**:
    โน้ต 223 ตัวทำให้ช่องนั้นกว้าง 1,396px ดันตารางเป็น 2,249px ในกรอบ 1,078px →
    **ปุ่มแก้ไข/ลบไปอยู่ที่ x=2,212 คือนอกจอ** แก้/ลบรายการนั้นไม่ได้เลยจนกว่าจะเลื่อนตารางไปไกลมาก
    · เพดานต้องมีผลเฉพาะโหมดตาราง (`lg:`) ไม่งั้นในโหมดการ์ดค่าจะไม่ชิดขอบขวาเหมือนช่องอื่น
  · ⚠️ **แถวที่ไม่มีข้อมูลเลยสักช่องต้องใส่คลาส `row-no-data`** — บนจอแคบจะยุบเหลือบรรทัดเดียว
    ("ม.ค. · ยังไม่มีข้อมูล") · วัดจริงตอนยังไม่ยุบ (หน้ารายปีของร้านที่เริ่มใช้กลางปี บนจอ 375):
    6 จาก 8 การ์ดมีแต่ขีด กินพื้นที่ **1,884 จาก 2,512px = 75%** ต้องปัดผ่านความว่างเปล่าราว 2 จอครึ่ง
    · หลังยุบเหลือ 42px/ใบ = 29%
  · วัดจริงก่อนแก้: ตารางประวัติกว้าง **727px ในกรอบ 317px** · หน้ารวมร้านกว้างกว่านั้น →
    **คอลัมน์กำไรอยู่นอกจอ** ทั้งที่เป็นตัวเลขเดียวที่แอปนี้มีไว้เพื่อบอก และผู้ใช้กรอกบนมือถือเป็นหลัก
  · CSS อยู่ใน `includes/header.php` · **ชื่อคอลัมน์ที่แปะหน้าค่าแต่ละช่องมาจาก `<thead>` ของตารางนั้นเอง**
    (สคริปต์ใน `includes/footer.php`) — ⚠️ **ห้ามพิมพ์ชื่อคอลัมน์ซ้ำไว้ที่ `<td>`** ไม่งั้นวันที่ใครสลับคอลัมน์
    ป้ายจะชี้ผิดช่องเงียบ ๆ · ตัวแปะเดินด้วย **เลขคอลัมน์จริง** (กาง `colspan` ออกก่อน) —
    เคยใช้ลำดับช่องแล้วแถว "รวมทุกร้าน" (ช่องแรกกิน 2 คอลัมน์) ป้ายเลื่อนทั้งแถว
  · ⚠️ **ตารางกรอกหลายวันใน `add-record.php` ตั้งใจไม่แปลง** — มันเป็นฟอร์มที่ JS ผูกกับโครง
    `tbody tr` + ลำดับ input (วางจาก Excel · เติมค่าเดิม) และฝั่ง JS ไม่มีตัวรันเทสต์ · ใช้
    `sticky-first-col` ตรึงคอลัมน์วันที่แทน
  · ⚠️⚠️ **กริดฤดูกาลในหน้ารายปีก็ตั้งใจไม่แปลงเหมือนกัน** — มันคือ **ตารางความร้อนที่ต้องอ่าน
    เป็น 2 มิติ** จุดประสงค์ทั้งหมดคือ "เดือนเดียวกันเทียบข้ามหลายปีติด ๆ" (เขียนไว้ใต้หัวข้อเอง)
    · วัดจริงตอนเป็นการ์ด (จอ 375): แต่ละปีเป็นการ์ดสูง **393px** เรียง 12 เดือนลงมา 3 ปี = **1,209px**
      → ม.ค. ของปีหนึ่งห่างจาก ม.ค. ของอีกปี ~400px **เทียบข้ามปีไม่ได้เลย** = ฟีเจอร์ตายบนมือถือ
    · ใช้ `sticky-first-col` + `min-w-[46rem]` แทน → สูง **132px** เห็น 3 เดือนพร้อมกันทั้ง 3 ปี
      ปัดขวาดูเดือนถัดไปโดยคอลัมน์ปียังอยู่
- ⚠️ **ปุ่มบนมือถือต้องมีพื้นที่กด ≥ 44px — ใช้คลาส `tap-target`** (ขยายด้วย `::after` ที่มองไม่เห็น
  หน้าตาจึงไม่เปลี่ยน) · วัดจริงก่อนแก้: `ลบ` = 46×24px · `แก้ไข` = 60×26px · **ปุ่ม `×` ลบแถว = 11×18px**
  — ปุ่มที่เล็กที่สุดในหน้าคือปุ่มที่อันตรายที่สุด และอยู่ติดปุ่มที่ใช้บ่อยกว่า
- ⚠️ **ห้ามใช้ `text-slate-500` กับข้อความที่ต้องอ่าน** — วัดจริงได้คอนทราสต์ **3.69 : 1** (เกณฑ์ 4.5)
  · ใช้ `text-slate-400` แทน · ตลกร้ายคือข้อความที่จางที่สุดคือข้อความที่ "สอนวิธีใช้" พอดี
  · ⚠️⚠️ **`text-slate-600` หลุดเข้ามาทีหลัง 8 จุด** ทั้งที่จางกว่าอีก — วัดได้ **2.32 : 1**
    (rgb(71,85,105) บนพื้นการ์ด rgb(11,23,57)) · หนักสุดคือเครื่องหมาย "ไม่มีข้อมูล" ในกริดฤดูกาล
    16 ช่อง = ช่องที่บอกว่า "ปีนั้นยังไม่มีข้อมูล" กลายเป็นช่องที่มองแทบไม่เห็น
    · เขียนกฎไว้ในเอกสารเฉย ๆ ไม่พอ — `SharedHelperContractTest::testNobodyUsesGreyTooFaintToRead()`
      กวาดห้าม `text-slate-500|600|700` และ `text-gray-500|600` แล้ว
- ⚠️⚠️⚠️ **ปุ่มพื้นไล่สี: เครื่องวัดคอนทราสต์แบบอ่าน `background-color` มองไม่เห็น**
  · element ที่ใช้ `background: linear-gradient(...)` มี `background-color` เป็น **โปร่งใสเสมอ**
    ตัวตรวจจึงเดินผ่านปุ่มทั้งใบไปใช้สีการ์ดข้างหลัง แล้วรายงานว่า "ผ่าน" ทั้งที่ตัวอักษรอยู่บนสีสด
  · วัดจริงหลังแก้เครื่องวัดให้อ่าน `background-image` ด้วย: **ปุ่มทั้ง 4 แบบตกเกณฑ์หมด** —
    ส้ม (ปุ่มหลัก "บันทึกข้อมูล") **2.80** · ฟ้า **2.43** · แดง **3.76** · ม่วง **4.23** (เกณฑ์ 4.5)
    ตัวที่แย่ที่สุดคือปุ่มที่ผู้ใช้กดทุกวัน
  · แก้แล้วโดยลดเฉดลงหนึ่งขั้น: `#c2410c→#9a3412` · `#0e7490→#0369a1` · `#dc2626→#991b1b` ·
    `#4f46e5→#7c3aed` — **[เจ้าของระบบตัดสิน 2026-08-09]** ยอมให้หน้าตาเข้มขึ้นเพื่อให้ผ่านเกณฑ์
  · `testWhiteTextOnColouredButtonsIsDarkEnough()` คำนวณคอนทราสต์จากเลขสีใน CSS จริง
    (ไม่ได้เทียบกับรายชื่อสีที่อนุญาต) เปลี่ยนเป็นสีอะไรก็ได้ ขอแค่ผ่าน
  · ⚠️⚠️⚠️ **สีปุ่มอยู่ที่ `includes/brand-colors.php` ที่เดียว — ทุกหน้าต้อง `require` แล้วใช้
    `var(--btn-…)` ห้ามเขียนเลขสีเอง** · `login.php` · `forgot-password.php` ·
    `reset-password.php` **ไม่ได้ใช้ `header.php`** (มี `<head>` ของตัวเอง) และเคยนิยาม
    `.btn-orange` ซ้ำไว้เอง → รอบที่แก้คอนทราสต์แก้แค่ `header.php` **ปุ่ม "เข้าสู่ระบบ"
    จึงยังตกที่ 2.80 : 1 อยู่** ทั้งที่ปุ่มหน้าอื่นผ่านหมด และแอปมีส้มสองเฉดพร้อมกัน
    ซึ่งแย่กว่าตอนก่อนแก้
    · ⚠️⚠️ **ตัวกวาดที่เขียนไว้กันเรื่องนี้เองก็มีรูโหว่แบบเดียวกัน** — มันอ่านแค่
      `includes/header.php` ไฟล์เดียว จึงเขียวอยู่ทั้งที่ของจริงยังพัง · ตอนนี้อ่านจาก
      `brand-colors.php` และมี `testNobodyWritesButtonColoursByHand()` กวาดทุกไฟล์คู่กัน
    · ⚠️ `error.php` ไม่ใช้ไฟล์นี้โดยตั้งใจ (ต้องขึ้นได้แม้ระบบพัง ห้ามพึ่ง include)
    · ⚠️ **คอมเมนต์ในไฟล์นี้ห้ามเขียนข้อความที่อยู่บนหน้าจอแบบคำต่อคำ** — ไฟล์ถูกส่งไป
      ทุกหน้ารวมหน้าที่ยังไม่ล็อกอิน `VerifyEmailPageTest` ค้นด้วยสตริงตรง ๆ จึงแดงได้
      โดยที่หน้าเว็บไม่ผิดอะไร (เจอมาแล้ว) — และไม่ควรทำให้เทสต์นั้นฉลาดขึ้น เพราะความ
      ตรงไปตรงมาของมันคือสิ่งที่ทำให้จับของจริงได้
- ⚠️⚠️ **ป้ายชื่อคอลัมน์ในโหมดการ์ดต้องเป็น `<span>` จริงใน DOM ห้ามใช้ `::before { content }`**
  · บนจอ < 1024px `thead` ถูก `display: none` → **หัวคอลัมน์หายจากสิ่งที่โปรแกรมอ่านหน้าจอเห็น**
    ป้ายที่แปะหน้าค่าจึงเป็นสิ่งเดียวที่บอกว่าเลขนั้นคืออะไร
  · ข้อความที่ CSS สร้างขึ้น โปรแกรมอ่านหน้าจอบางตัวไม่อ่าน (Chrome/Firefox อ่าน ·
    **VoiceOver ไม่แน่นอน** ซึ่งคือเครื่องของผู้ใช้ส่วนใหญ่) · ตอนนี้สคริปต์ใน `footer.php`
    ใส่ `<span class="cell-label">` ให้ และ CSS ซ่อนมันตอนจอกว้าง (ตอนนั้น `thead` ทำหน้าที่แทน)
  · ⚠️ ต้องกันเติมซ้ำ — ฟังก์ชันถูกเรียกได้มากกว่าหนึ่งครั้ง

  · ใช้ `data-a11y-base` + เลขแถวจาก `refresh()` — **เลขเดียวกับคอลัมน์ "#" ที่ผู้ใช้เห็น**

  ตั้ง `aria-labelledby`) · ห้ามพิมพ์ชื่อตารางซ้ำเป็นข้อความใหม่ · `<th>` ทุกตัวมี `scope="col"`
