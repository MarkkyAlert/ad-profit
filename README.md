# 📊 Ad‑Profit — ระบบบันทึกรายได้/ค่าโฆษณา/กำไร (รองรับหลายร้าน)

สรุปสั้น ๆ:
- คุณมี “หลายร้าน” ได้ (เช่น ร้าน A / ร้าน B)
- แต่ละวันคุณบันทึก **รายได้** + **ค่าโฆษณา**
- ระบบคำนวณ **กำไร = รายได้ − ค่าโฆษณา** ให้
- มีหน้า **Dashboard / History / Overview (รวมทุกร้าน) / Annual (รายปี)**
- ส่งออกได้ **2 แบบ**: ไฟล์ **CSV รายเดือน** (จากหน้าประวัติ) และ **ไฟล์ Excel รายปีหลายชีต** (จากหน้าสรุปรายปี)

✨ สิ่งที่ควรรู้ก่อน (กันเข้าใจผิด)
- โปรเจกต์นี้เป็น **PHP แบบไฟล์** (ไม่ใช่ Laravel) เพื่อให้มือใหม่ “ไล่โค้ดตามได้ง่าย”
- ระบบนี้มีผู้ใช้ **role เดียว** (ทุกบัญชีทำได้เท่ากัน) — ไม่มีหน้า admin/staff แยก
- ข้อมูลถูกแยกตาม **ผู้ใช้** และ **ร้าน** (User A จะไม่เห็นข้อมูลของ User B)

> โปรเจกต์นี้ถูกสร้างโดย AI และถูกจัดโครงสร้างไว้ให้ “อ่านง่ายและแก้ได้เป็นจุด ๆ”
> เหมาะมากสำหรับทำเป็น template, ใช้สอน, เดโม, และส่งโปรเจกต์

📌 เอกสารประกอบที่แนะนำให้เปิดคู่กัน:
- ✅ `docs/QA_CHECKLIST.md` — เช็กลิสต์ทดสอบก่อนขาย/ขึ้นระบบจริง
- 📘 `docs/INSTALL.md` — คู่มือติดตั้งแบบละเอียด
- 🧭 `docs/FLOW.md` — ผัง flow ทั้งระบบ
- 🗺️ `docs/WHERE_TO_EDIT.md` — อยากแก้ฟีเจอร์นี้ ไปแก้ไฟล์ไหน
- 🏗️ `docs/ARCHITECTURE.md` — โครงสร้างระบบ

# 1️⃣ ระบบนี้คืออะไร?

ลองนึกภาพว่า…

  - วันนี้กำไรเท่าไหร่

# 2️⃣ ภาพรวมการทำงานของระบบ (ไม่ใช้ศัพท์ยาก)

## 2.1 เรื่องราวแบบ “ผู้ใช้กดปุ่ม → ระบบทำอะไร”

ตัวอย่าง: ผู้ใช้กด “บันทึกข้อมูลรายวัน”
1) ผู้ใช้กรอกฟอร์มในหน้า `add-record.php`
2) กดปุ่มบันทึก
3) หน้าเว็บส่งข้อมูลไปที่ `api/records.php`
4) ระบบตรวจว่า “นี่คือคนที่ login อยู่จริงไหม?”
5) ระบบตรวจว่า “ฟอร์มนี้มาจากเว็บเราจริงไหม?” (กันคนอื่นแอบยิง)
6) ระบบบันทึกลงฐานข้อมูล
7) ระบบพากลับไปหน้าเดิม พร้อมข้อความสำเร็จ

## 2.2 คำว่า Controller / Service / Repository คืออะไร?

ไม่ต้องกลัวคำศัพท์ครับ 🙌

ลองเทียบกับ “ร้านอาหาร”:

- **Controller** = พนักงานรับออเดอร์
  - รับข้อมูลจากลูกค้า
  - เช็คว่าลูกค้ากรอกครบไหม
  - แล้วส่งต่อให้คนทำอาหาร

- **Service** = เชฟ
  - ตัดสินใจว่า “ต้องทำอะไรก่อนหลัง”
  - เช่น ต้องตรวจสิทธิ์, ตรวจเลขติดลบ, คำนวณกำไร

- **Repository** = คนเดินไปหยิบวัตถุดิบ / เปิดคลัง
  - หน้าที่เดียวคือ “คุยกับฐานข้อมูล”
  - เช่น เพิ่ม/แก้/ลบ/ค้นข้อมูล

- **Database (ฐานข้อมูล)** = คลังวัตถุดิบ / สมุดบัญชี
  - ที่เก็บข้อมูลจริงทั้งหมด

📌 ทำไมต้องแยกแบบนี้?
- เวลาเว็บพัง เราไล่ได้เป็นขั้น ๆ
- เวลาอยากเพิ่มฟีเจอร์ เรารู้ว่าควรเพิ่มตรงไหน
- ลดโอกาส “แก้มั่วแล้วพังทั้งระบบ”

## 2.3 คำศัพท์ที่เจอบ่อย (แบบคนไม่ใช่สายโค้ด)

- **API** = จุดรับคำสั่งจากหน้าเว็บ (เหมือน “ช่องรับออเดอร์”)
- **JSON** = ข้อมูลแบบข้อความที่ระบบส่งให้หน้าเว็บ/โปรแกรมอ่าน (มักใช้ใน API)
- **Session** = บัตรผ่านหลัง login (เว็บใช้จำว่าเราเป็นใคร)
- **Cookie** = กล่องเก็บ session ในเบราว์เซอร์
- **CSRF Token** = รหัสลับในฟอร์ม กันคนอื่นแอบกดแทนเรา
- **XSS** = การฝังโค้ดอันตรายในข้อความ แล้วเว็บเผลอเอาไปแสดงจน “รันได้”
- **SQL** = ประโยคที่ใช้ “ถาม/บันทึก” ข้อมูลในฐานข้อมูล
- **Composer** = โปรแกรมช่วยดาวน์โหลดของสำเร็จรูป (ไลบรารี) ให้โปรเจกต์
- **Cron** = งานที่ตั้งเวลาให้รันอัตโนมัติ (เช่น ล้างข้อมูลเก่า)
- **HTTPS** = เว็บที่เข้ารหัส ปกติจะเห็นรูปกุญแจในเบราว์เซอร์
- **`e()`** = ฟังก์ชันช่วย “แปลงข้อความให้ปลอดภัยก่อนแสดงผล” (กัน XSS)

# 3️⃣ โครงสร้างโฟลเดอร์ (ดูแล้วไม่งง)

ภาพรวมไฟล์สำคัญ (แบบอ่านง่าย):

```
/ (root)
  login.php, dashboard.php, history.php, ...   <- หน้าเว็บที่คนใช้เห็น
  api/                                         <- จุดรับข้อมูลจากฟอร์ม/ส่ง JSON (ข้อมูลแบบข้อความให้หน้าเว็บอ่าน)
  app/
    Services/                                  <- กฎการทำงาน (เชฟ)
    Repositories/                              <- คุยกับฐานข้อมูล (คลัง)
  includes/                                    <- ของส่วนกลาง (ตั้งค่า, helper, auth)
  database/                                    <- ไฟล์สร้างตาราง + ข้อมูลตัวอย่าง
  docs/                                        <- เอกสารอธิบายระบบ
  cron/                                        <- งานที่ตั้งเวลาให้รันอัตโนมัติ (prod)
  logs/                                        <- ที่เก็บ log เวลา error
  vendor/                                      <- ของสำเร็จรูปจาก Composer (ห้ามแก้)
```

## 3.1 โฟลเดอร์/ไฟล์ที่ “มือใหม่แก้ได้” ✅

- `*.php` ที่อยู่ใน root เช่น
  - `login.php` (หน้า login/สมัคร)
  - `dashboard.php` (หน้าแดชบอร์ด)
  - `history.php` (หน้าประวัติ)
  - `shops.php` (หน้าร้าน)
  - `profile.php` (หน้าโปรไฟล์)

- `includes/header.php`, `includes/footer.php`
  - แก้เมนู, ปุ่ม, layout, ข้อความ, UI ได้

- `docs/*` (รวม `docs/QA_CHECKLIST.md`)
  - แก้เอกสาร/คำอธิบาย/คู่มือ

## 3.2 โฟลเดอร์ที่ “แก้ได้ แต่ต้องระวัง” ⚠️

- `api/*.php`
  - เป็นจุดรับข้อมูลจากฟอร์ม
  - ถ้าแก้ผิด จะทำให้บันทึก/แก้ไขข้อมูลไม่ได้

- `app/Services/*.php`
  - กฎการทำงานหลัก
  - เหมาะสำหรับเพิ่มเงื่อนไข/ปรับสูตรคำนวณ

- `app/Repositories/*.php`
  - มีคำสั่งฐานข้อมูล (SQL)
  - แก้ได้ แต่ควรทำอย่างระวังมาก

## 3.3 โฟลเดอร์ที่ “ห้ามยุ่งถ้าไม่เข้าใจ” ⛔

- `vendor/`
  - เป็นไลบรารีภายนอก (เช่น ส่งอีเมล)
  - อย่าแก้ตรงนี้

- `includes/bootstrap.php`
  - ไฟล์เริ่มระบบ: เปิด session, ต่อ DB, autoload
  - แก้มั่วแล้วเว็บพังทั้งระบบได้

- `includes/functions.php`
  - helper สำคัญ เช่น escape กัน XSS, CSRF, flash message
  - แก้ผิด = ช่องโหว่/พังทั้งระบบ

📍 “อยากแก้ฟีเจอร์นี้ ไปไฟล์ไหน?”
- ดูไฟล์ `WHERE_TO_EDIT.md`

# 4️⃣ Flow สำคัญของระบบ (Step by Step)

> ส่วนนี้ตั้งใจเขียนให้คนไม่เก่งโค้ดก็ไล่ตามได้

## 4.1 Register (สมัครสมาชิก)
1) เปิด `login.php` → แท็บสมัครสมาชิก
2) กรอกอีเมล + รหัสผ่าน
3) ระบบสร้างบัญชี + สร้าง “ร้านแรก” ให้อัตโนมัติ
4) ระบบพาไป `dashboard.php`

ทำไมต้องสร้างร้านแรก?
- เพราะข้อมูลทุกอย่างในระบบ “ผูกกับร้าน”
- กันข้อมูลปนกันเวลามีหลายร้าน

## 4.2 Login (เข้าสู่ระบบ)
1) กรอกอีเมล + รหัสผ่าน
2) ระบบเช็คว่าตรงกับในฐานข้อมูลไหม
3) ระบบสร้าง “บัตรผ่าน” ให้ในเบราว์เซอร์ (เรียกว่า session)
4) ระบบพาไป `dashboard.php`

## 4.3 Shops (สร้าง/สลับ/ลบร้าน)
1) สร้างร้านใหม่ที่ `shops.php`
2) ระบบบันทึกร้านลงฐานข้อมูล
3) ระบบสลับไปใช้ร้านนั้นทันที
4) ข้อมูล Dashboard/History จะเป็นของ “ร้านปัจจุบัน”

## 4.4 Daily Records (บันทึกรายวัน) + History (แก้ไข/ลบ)
1) เปิด `add-record.php`
2) ใส่วันที่ + รายได้ + ค่าโฆษณา
3) กดบันทึก
4) เปิด `history.php` เพื่อดูรายการทั้งหมดของเดือนนั้น
5) แก้ไข/ลบรายการได้

ทำไมต้องมีหน้า History?
- เพราะเป็น “หลักฐานย้อนหลัง”
- ตรวจยอดรวมทั้งเดือน
- export ออกเป็น CSV ได้

## 4.5 Goals (ตั้งเป้ารายเดือน)
1) ที่ `dashboard.php` ตั้งเป้ารายได้/กำไรของเดือน
2) ระบบเก็บเป้าไว้
3) Dashboard แสดง progress ว่าถึงเป้าหรือยัง

## 4.6 Overview (รวมทุกร้าน)
1) ถ้าคุณมี 2 ร้านขึ้นไป
2) เปิด `overview.php`
3) ระบบจะเอาข้อมูลแต่ละร้านมาเทียบกัน

## 4.7 Annual (สรุปรายปี)
1) เปิด `annual.php`
2) เลือกปี
3) ระบบสรุปยอดเป็น 12 เดือน

## 4.8 Export CSV
1) ไป `history.php`
2) กด Export CSV
3) ได้ไฟล์เปิดใน Excel ได้ (รองรับภาษาไทย)

## 4.9 Forgot / Reset Password
1) ขอรีเซ็ตที่ `forgot-password.php`
2) ระบบส่งลิงก์ไปอีเมล (หรือ Dev mode แสดงลิงก์บนหน้า)
3) เปิดลิงก์ `reset-password.php?token=...`
4) ตั้งรหัสใหม่

### วิธี B: ใช้คำสั่ง (เร็ว)
ดูคำสั่งตัวอย่างใน `docs/INSTALL.md`

## 5.4 ตั้งค่า `.env`
- [ ] คัดลอกไฟล์ `.env.example` เป็น `.env`
- [ ] เริ่มจากค่าเดิมก่อน แล้วค่อยปรับทีหลัง

## 5.5 เปิดใช้งาน
- [ ] เปิด Apache + MySQL ใน XAMPP
- [ ] เข้า `http://localhost/ad-profit/`

## 5.6 Error ที่มือใหม่พลาดบ่อย (และแปลว่าอะไร)

- ❗ **DB connection failed**
  - แปลว่า MySQL ยังไม่ start หรือกรอก DB_USER/DB_PASS ไม่ถูก

- ❗ เปิดเว็บแล้วเจอหน้า **503 “ต้องอัปเกรดโครงสร้างฐานข้อมูล”**
  - แปลว่า schema ใน DB ยังไม่ตรงกับเวอร์ชันโค้ด
  - วิธีแก้: import `database/schema.sql` ใหม่ หรือทำตาม `docs/INSTALL.md` ข้อ Migration

- ❗ เจอ error ประมาณ **"Class 'PHPMailer...' not found"**
  - แปลว่าโฟลเดอร์ `vendor/` ไม่ครบ (ของสำเร็จรูปสำหรับส่งอีเมล)
  - วิธีแก้: รัน `composer install` หรือให้แน่ใจว่ามีโฟลเดอร์ `vendor/` มาพร้อมโปรเจกต์

- ❗ Production แล้ว “login ไม่ติด / session หาย”
  - ถ้า `APP_ENV=production` ระบบจะตั้ง cookie แบบ **Secure**
  - ถ้าเข้าเว็บด้วย **HTTP** (ไม่ใช่ HTTPS) จะเกิดอาการเหมือน login ไม่ติด
  - วิธีแก้: ใช้ HTTPS และตั้ง `APP_URL` ให้ถูก

# 6️⃣ การตั้งค่า (Config)

## 6.1 ไฟล์ config อยู่ตรงไหน?
- ไฟล์ที่คุณควรแก้เป็นหลัก: **`.env`**
- ไฟล์ที่อ่านค่า `.env` แล้วตั้งค่าระบบ: `includes/config.php`

## 6.2 ค่าที่ “ควรแก้” บ่อย ✅

ตัวอย่าง `.env` แบบ local/dev:
```env
APP_ENV=development
APP_NAME="Ad Profit"
EXPOSE_DEV_RESET_LINK=true

DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=ad_profit
DB_USER=root
DB_PASS=
```

ตัวอย่าง `.env` แบบ production (สำคัญมาก):
```env
APP_ENV=production
APP_URL=https://example.com/ad-profit

DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=ad_profit
DB_USER=your_user
DB_PASS=your_password

MAIL_ENABLED=true
MAIL_HOST=smtp.gmail.com
MAIL_PORT=587
MAIL_USERNAME=your_email
MAIL_PASSWORD=your_app_password
MAIL_FROM_ADDRESS=your_email
MAIL_FROM_NAME="Ad Profit"
```

ความหมายแบบง่าย:
- `APP_ENV`
  - `development` = โหมดทำเดโม/ทำงานในเครื่อง
  - `production` = โหมดใช้งานจริง (เข้มเรื่องความปลอดภัย)

- `APP_URL` (สำคัญตอน production)
  - คือ URL จริงของเว็บ เช่น `https://example.com/ad-profit`

- `DB_*`
  - คือข้อมูลการต่อฐานข้อมูล

- `EXPOSE_DEV_RESET_LINK`
  - ถ้าเปิด (และเป็น development) จะโชว์ลิงก์ reset password บนหน้าเลย
  - เหมาะสำหรับเดโม/สอน ไม่เหมาะกับ production

- `SESSION_*_TIMEOUT_SECONDS`
  - ตั้งว่า “นานแค่ไหนถึงจะหลุด”

- `MAIL_*`
  - เอาไว้ส่งอีเมลรีเซ็ตรหัสผ่านจริง

## 6.3 ค่าที่ “ห้ามแก้ถ้าไม่เข้าใจ” ⛔

- `SCHEMA_GUARD_ENABLED`
  - ปกติควรเปิดไว้เพื่อกัน DB โครงสร้างไม่ตรงแล้วระบบพังเงียบ ๆ

- `TRUST_PROXY` / `TRUSTED_PROXIES`
  - เปิดเฉพาะกรณีมี “ตัวกลางหน้าเว็บ” ที่คุณควบคุมได้จริง (เช่น มีระบบส่งต่อ request ก่อนถึงเว็บ)

# 7️⃣ ใช้งานระบบยังไง (Usage)

เริ่มจากตรงไหน?
1) เปิดเว็บ → จะถูกพาไป `login.php`
2) สมัครสมาชิก หรือ login
3) เข้าหน้า `dashboard.php`

คุณทำอะไรได้บ้าง?
- 🏪 **จัดการร้าน**: สร้าง/สลับ/เปลี่ยนชื่อ/ลบ ที่ `shops.php`
- ➕ **เพิ่มข้อมูลรายวัน**: ที่ `add-record.php` — **มี 4 ทาง เลือกได้ตามสถานการณ์** (ดูหัวข้อถัดไป)
- 🧾 **ดูประวัติ**: ที่ `history.php` (แก้ไข/ลบ/ดาวน์โหลด CSV ของเดือนนั้น)
- 🎯 **ตั้งเป้ารายเดือน**: ที่ `dashboard.php` (ตั้งเป้ารายได้และเป้ากำไร)
- 🏪📊 **รวมทุกร้าน**: ที่ `overview.php` (ต้องมีอย่างน้อย 2 ร้าน) — ดูได้ 3 มุม: รายวัน / รายเดือน / รายปี
- 📅 **สรุปรายปี**: ที่ `annual.php` (มีความคืบหน้าเป้า · ประมาณการสิ้นปี · กริดฤดูกาล · ปุ่มดาวน์โหลด Excel)
- 👤 **แก้โปรไฟล์/เปลี่ยนอีเมล/เปลี่ยนรหัสผ่าน**: ที่ `profile.php`

## 📝 กรอกข้อมูลได้ 4 ทาง — เลือกให้ตรงกับงาน

ทุกทางอยู่ในหน้า `add-record.php` หน้าเดียวกัน · **สองทางล่างถูกพับเก็บไว้ ต้องกดหัวข้อเพื่อเปิด**

| ทาง | เหมาะกับ | อยู่ตรงไหน |
|---|---|---|
| **1. กรอกทีละวัน** | บันทึกของวันนี้ตามปกติ | ฟอร์มบนสุด — เลือกวันแล้วกรอกรายได้/ค่าแอด/โน้ต |
| **2. ตารางกรอกหลายวัน** | กรอกย้อนหลังหลายวันรวดเดียว | กดหัวข้อ **"กรอกหลายวัน — ย้อนหลังทีละหลายวัน"** → เลือกเดือน → ตารางจะขึ้นมาให้กรอกทีละแถว |
| **3. วางจาก Excel** | มีข้อมูลอยู่ใน Excel/Google Sheets แล้ว | เปิดตารางกรอกหลายวัน แล้ว **ก๊อปคอลัมน์จาก Excel มาวางในตารางได้เลย** |
| **4. นำเข้าไฟล์ CSV** | มีข้อมูลย้อนหลังเยอะมาก (เป็นเดือน/เป็นปี) | กดหัวข้อ **"นำเข้าไฟล์ CSV — ย้ายข้อมูลจาก Excel เข้ามาทั้งไฟล์"** → เลือกไฟล์ → กด **"↑ นำเข้า"** |

**ตัวช่วยในตารางกรอกหลายวัน:**
- ปุ่ม **"เติมทั้งเดือน"** — ใส่วันที่ให้ครบทุกวันของเดือนที่เลือก และ**ดึงยอดเดิมของวันที่เคยบันทึกไว้มาแสดง**ให้แก้ได้เลย
- ระบบเติมโน้ตเดิมกลับมาให้เสมอ — ถ้าเว้นช่องโน้ตไว้ทั้งที่วันนั้นเคยมีโน้ต ระบบจะเตือนก่อน ไม่ลบทิ้งเงียบ ๆ

**ไฟล์ CSV ที่นำเข้าได้ต้องมีคอลัมน์:** `วันที่` · `รายได้` · `ค่าแอด` · `โน้ต` (ไม่บังคับ)
- ชื่อคอลัมน์ใช้แทนกันได้: `วันที่`/`วัน`/`date` · `รายได้`/`ยอดขาย`/`revenue` · `ค่าแอด`/`ค่าโฆษณา`/`ad_cost`
- ไฟล์ที่ดาวน์โหลดออกไปจากระบบ นำกลับเข้ามาได้เลย
- ⚠️ **วันที่แบบ `05/03/2026` ระบบจะปฏิเสธ** เพราะอ่านได้ทั้ง 5 มี.ค. และ 3 พ.ค. — ใช้ `2026-03-05` จะชัดเจนที่สุด
- ⚠️ ช่องยอดที่เว้นว่าง ระบบจะปฏิเสธ ไม่เดาให้เป็น 0

## 📤 ดาวน์โหลดข้อมูลออกไปได้ 2 แบบ

| แบบ | ได้อะไร | กดที่ไหน |
|---|---|---|
| **CSV รายเดือน** | ทุกวันของเดือนนั้น + แถวรวม เปิดใน Excel ได้ทันที (ภาษาไทยไม่เพี้ยน) | หน้า `history.php` ปุ่ม **"📥 Export CSV"** |
| **Excel รายปี (5–6 ชีต)** | **รายปี** (สรุป + เทียบปีก่อน + ประมาณการ) · **รายเดือน** · **รายวัน** · **เป้าหมาย** · **เทียบร้าน** · และ **ฤดูกาล** (โผล่เมื่อมีข้อมูลตั้งแต่ 2 ปีขึ้นไป) พร้อมกราฟฝังในไฟล์ | หน้า `annual.php` ปุ่ม **"📊 ดาวน์โหลดรายงานประจำปี (Excel)"** |

ถ้าใช้งานผิด จะเกิดอะไร?

# 8️⃣ จุดที่ต้องระวัง (สำคัญมาก)

## 8.1 อย่าแก้/อย่าลบสิ่งนี้ ถ้ายังไม่เข้าใจ
- ⛔ `vendor/` (ไลบรารี)
- ⛔ `includes/bootstrap.php` (ไฟล์เริ่มระบบ)
- ⛔ `includes/functions.php` (ของกัน XSS/CSRF ฯลฯ)

## 8.2 กฎง่าย ๆ ก่อนแก้ระบบ (กันพัง)
- ✅ ถ้าจะเพิ่ม/แก้ข้อมูลใน DB: เริ่มที่ `app/Repositories/*`
- ✅ กฎธุรกิจ/คำนวณ: อยู่ที่ `app/Services/*`
- ✅ `api/*` เอาไว้รับข้อมูล/ตรวจ CSRF/เรียก service
- ✅ เวลาแสดงข้อความจากผู้ใช้/DB ต้อง escape ด้วย `e()` (แปลงข้อความให้ปลอดภัยก่อนแสดง)

(พูดง่าย ๆ: “แยกหน้าที่” แล้วระบบจะไม่เละ)

## 8.3 ถ้าระบบพัง ควรดูตรงไหนก่อน? 🚑

ทำตามนี้ทีละข้อ:
1) ดูว่าพังหน้าไหน (เช่น `dashboard.php` หรือ `api/records.php`)
2) เปิดไฟล์ log (ดูค่า `LOG_FILE` ในไฟล์ `.env`)
   - ถ้าไม่ได้ตั้ง `LOG_FILE` มักอยู่ในโฟลเดอร์ Temp ของเครื่อง เช่น `%TEMP%\ad-profit\php-error.log`
   - ถ้าอยากให้ log อยู่ในโปรเจกต์ ให้ตั้ง `LOG_FILE=logs/php-error.log`
3) เช็คว่า Apache + MySQL ยังเปิดอยู่
4) เช็ค `.env` ว่าต่อ DB ถูกไหม (`DB_HOST/DB_USER/DB_PASS`)
5) ถ้าเจอ 503 เรื่อง schema:
   - import `database/schema.sql` ใหม่
   - หรือทำตาม `docs/INSTALL.md` หัวข้อ Migration

## 8.4 ก่อนจะขาย/ก่อนขึ้น production
- [ ] รันเช็กลิสต์ใน `docs/QA_CHECKLIST.md` ให้ครบ
- [ ] ตั้ง `APP_ENV=production`
- [ ] ตั้ง `APP_URL` เป็น **https://...**
- [ ] ทดสอบ “ลืมรหัสผ่าน” ว่าส่งอีเมลได้จริง (ถ้าจะใช้จริง)
- [ ] ตั้ง cron อย่างน้อย 2 ตัวใน `cron/` (ดู `docs/INSTALL.md`)

# 🔟 FAQ (คำถามที่มือใหม่ถามบ่อย)

### Q1: ใช้ PHP เวอร์ชันอะไร?
- แนะนำ **PHP 8.1+**

### Q2: ใช้ Shared Hosting ได้ไหม?
- ได้ ถ้า hosting นั้นมี:
  - PHP 8.1+
  - MySQL/MariaDB
  - เปิด HTTPS ได้
- และคุณต้อง:
  - ตั้ง `.env` ให้ถูก
  - ตั้ง `APP_ENV=production` และ `APP_URL=https://...`

### Q3: ถ้าแก้แล้วพัง ทำยังไง?
1) ดูไฟล์ log ก่อน (ดูค่า `LOG_FILE` ใน `.env`)
2) ถ้ายังไม่เข้าใจ ให้ย้อนดูว่าแก้ไฟล์ไหน
3) แนะนำให้เริ่มแก้จากไฟล์ใน `WHERE_TO_EDIT.md`
4) ถ้าคุณใช้ git (เครื่องมือเก็บประวัติโค้ด): สามารถ “ย้อนกลับก่อนแก้” ได้ แล้วค่อยแก้ใหม่ทีละจุด

### Q4: เพิ่มฟีเจอร์เองได้ไหม?
- ได้ครับ และแนะนำให้เพิ่มตาม “ทางเดิน” นี้:
  1) เพิ่ม UI ในหน้า `*.php`
  2) ส่งข้อมูลไป `api/*.php`
  3) ใส่กฎใน `app/Services/*`
  4) คุย DB ที่ `app/Repositories/*`
  5) ถ้าต้องเพิ่มตาราง/คอลัมน์: แก้ `database/schema.sql`

### Q5: ทำไม production แล้ว login ไม่ติด?
- เช็ค 2 อย่างนี้ก่อนเลย:
  - คุณเข้าเว็บด้วย **HTTPS** แล้วหรือยัง?
  - `APP_URL` ตั้งเป็น `https://...` แล้วหรือยัง?

### Q6: ลืมรหัสผ่านแล้วไม่เห็นอีเมล?
- ใน development:
  - เปิด `EXPOSE_DEV_RESET_LINK=true` แล้วระบบจะโชว์ลิงก์บนหน้า
- ใน production:
  - ต้องตั้ง `MAIL_ENABLED=true` และตั้งค่า `MAIL_*` ให้ถูก

### Q7: อยากทำระบบหลาย role (admin/staff/member) ได้ไหม?
- ทำได้ แต่โปรเจกต์นี้ “ยังไม่ได้ทำมาให้”
- ต้องเพิ่มตาราง/ฟิลด์ role และเพิ่มการเช็คสิทธิ์ในหลายจุด
- ถ้าคุณขายเป็น template แนะนำทำเป็น “เวอร์ชันถัดไป” เพื่อไม่ให้ scope บาน

## 🧾 สรุปสำหรับคนจะเอาไปขายเป็น template
- จุดขายของระบบนี้คือ: **โครงสร้างชัด, flow ครบ, ปลอดภัยระดับใช้งานเล็ก ๆ, สอนง่าย**
- ก่อนขายทุกครั้งให้ทำตาม `docs/QA_CHECKLIST.md`
- ถ้าจะขึ้น production จริง: ต้องใช้ HTTPS และตั้งค่า `.env` ให้ถูก

## 🛡️ Security Hardening ที่ทำไว้แล้ว
- **CSRF Protection**: ทุก state-changing POST action
- **Method Guard**: POST-only สำหรับ state-changing actions
- **Content-Type Guard**: ตรวจ Content-Type ของ POST request (415 ถ้าไม่ใช่ form)
- **Transaction + Row Locking**: RecordService, ShopService, ProfileService, GoalService ใช้ TX + `FOR UPDATE` lock
- **Rate Limiting**: auth actions และ profile changes
